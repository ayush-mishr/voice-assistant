# AWS API Gateway & Lambda Authorizer Setup Guide

This guide ensures you can deploy an authentic JWT Authorizer to protect your AWS API Gateway using the deployment package I just generated for you!

You will find a newly created file in your workspace: `authorizer.zip`. This contains the Python code and `pyjwt` library.

---

## Part 1: Setting up the Lambda Authorizer

### Step 1: Create the Lambda Function
1. In the **AWS Console**, search for **Lambda** and click **Create function**.
2. Select **Author from scratch**.
3. **Function name:** `jwt-authorizer`
4. **Runtime:** Select `Python 3.12` (or Python 3.11).
5. Architecture: `x86_64` (default)
6. Click **Create function**.

### Step 2: Upload the Deployment Package
1. On your new Lambda function page, scroll down to the **Code source** section.
2. On the right side, click the **Upload from** dropdown button.
3. Select **.zip file**.
4. Click **Upload** and select the `authorizer.zip` file located on your Desktop in the `voice-assistant` folder!
5. Click **Save**.

### Step 3: Add your Secret Key 
For the Lambda to validate the JWT correctly, it needs your secret key.
1. In the Lambda function page, switch to the **Configuration** tab.
2. In the left menu, click **Environment variables**.
3. Click **Edit**, then **Add environment variable**.
4. **Key:** `JWT_SECRET_KEY`
5. **Value:** `highly-secure-jwt-secret-key` *(or whatever you change it to in the future!)*
6. Click **Save**.

---

## Part 2: Attaching it to the API Gateway

### Step 1: Create the Authorizer in API Gateway
1. Go back to your **API Gateway** dashboard and click on your `voice-assistant-api`.
2. In the left sidebar under *Develop*, click **Authorization**.
3. You will see a list of your routes. Click on the Route you want to protect (e.g. `ANY /api/{proxy+}`).
4. Click **Create and attach an authorizer**.
5. **Authorizer type:** Select **Lambda**.
6. **Name:** `jwt-authorizer-link`
7. **Lambda function:** Select your new `jwt-authorizer` you created in Part 1.
8. **Payload format version:** Select `2.0`.
9. **Identity sources:** Ensure this says `$request.header.Authorization`.
10. Click **Create and attach**.

---

## Part 3: Testing the Protected API

Your backend is now protected exclusively by AWS! If an external user tries to access your API without a valid JSON Web Token generated by your login endpoint, Amazon will instantly return an `HTTP 401 Unauthorized` without ever polling your actual ECS server.

### Bypassing Auth for Login/Signup
Because users need to hit `/api/login` or `/api/signup` to *get* their token in the first place, we do not want the Authorizer blocking those requests. 

**I have just updated your Python Lambda code to handle this automatically!**
You do **not** need to create any custom API Gateway setup for this! You can actually go back to your API Gateway Routes page and **delete** those specific `POST` routes you were trying to make. 

The Lambda automatically scans the request, and if it sees the user is asking for `/api/login`, it safely lets them through to your backend!
